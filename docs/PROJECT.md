# 项目章程

状态：目标与边界文档；包含当前事实和未来目标。

## 背景

现有 RK 前端能表达合同版本、研究路线、尝试、数学 Claim、验证、审查、撤销和发布，但交互形态更接近控制台。MathVision 前端拥有成熟的聊天、Notebook、Workspace Explorer、LaTeX/PDF 和工作流图交互，但其底层对象主要是会话、消息和一次运行步骤，缺少 RK 的数学权威语义。

本项目以已经恢复的 MathVision 本地端作为交互基线，建设一个本地优先的 RK 数学研究工作台。

## 产品目标

### 1. 节点即线程

研究线程图中的每个节点都是可独立打开的持久线程。线程可以：

- 继续对话和运行；
- 暂停、恢复、分叉和回溯；
- 绑定父线程、工作项和尝试；
- 产生候选 Claim、工件和工具运行；
- 保留输入、输出、错误、费用和时间记录。

### 2. 双图分离

- 研究线程图回答“研究过程是怎么展开的”。
- 数学事实图回答“哪些结论当前可以依赖，它们依赖什么”。

两图可以互相跳转，但不能混用状态。一次模型运行成功不等于数学 Claim 已验证。

### 3. RK 保持权威边界

所有事实提升、合同修订、依赖闭包、撤销、独立审查和发布动作都由 RK 命令完成。前端消息、Notebook 输出和本地模型回答只能成为候选材料。

### 4. 本地优先

默认单机运行，不要求 MathVision 账号或远端身份系统。数据和工件首先保存在本地；需要外部模型、文献或协作服务时，必须显式配置并留下可审计记录。

## 当前范围

- 忠实恢复并维护现有 React 前端。
- 删除 MathVision 登录依赖和 Logo。
- 建立本地数据与请求适配层。
- 设计并实现研究线程领域对象。
- 将 RK 的研究、Claim、工具、工件、审查和发布能力接入工作台。
- 支持中英文界面。

## 非目标

- 不声称恢复了被压缩器删除的原始变量名、注释或目录结构。
- 不把本地模拟接口描述为真实推理后端。
- 不让前端绕过 RK 直接写入已验证事实。
- 恢复阶段不擅自重做视觉和交互。
- 本仓库不代替单独的许可审查和发布决定。

## 成功标准

一个最小可用版本必须同时满足：

1. 用户能从图中创建、打开、分叉和恢复研究线程。
2. 每个线程能运行至少一种模型和一种确定性工具，并保存完整记录。
3. 候选 Claim 能送入 RK 验证流程，但不能被前端直接标记为 VERIFIED。
4. 数学事实图能区分 VERIFIED 与 RESEARCH_HISTORY，并支持依赖和反向影响闭包。
5. 所有持久化写入都有冲突检测或显式版本规则。
6. 本地断网时，已有项目、线程、消息和工件仍可浏览。
